# SAR Oil-Spill Detection MVP (`ai/sar/`)

**Member 3 module** for SIH26143 — the first stage of the pipeline:

```
SAR image → detection → spill location + confidence → (drift / AIS modules, owned by others)
```

This is a lightweight, classical image-processing MVP — **not** a trained
deep-learning model — per the "working demo > complex model" rule for
tonight. It's written so the core thresholding/scoring step
(`candidate_mask()` + `score_contour()`) can later be swapped for a
trained segmentation model (e.g. U-Net) without touching the rest of the
pipeline (I/O, output image, JSON contract).

## 1. Install dependencies

```bash
cd ai/sar
pip install -r requirements.txt
```

## 2. Sample image

No real SAR scene was provided, so `sample_sar.png` is a **synthetic
demo image** (generated by `make_sample.py`): a speckled grey
background with a dark, elongated blob simulating an oil slick, plus a
small circular patch simulating a "look-alike" (e.g. a low-wind area)
— to demonstrate that the detector doesn't just flag every dark region.

To regenerate it, or to point at your own SAR image instead:

```bash
python make_sample.py               # regenerate sample_sar.png
python detect.py --image path/to/your_real_sar_image.png
```

Any standard image format OpenCV can decode (PNG/JPG/TIFF) works.
The image is read as grayscale.

## 3. Run detection

```bash
python detect.py
```

This runs on `sample_sar.png` by default and prints a summary, e.g.:

## 4. Where the output goes

- `output/detected_spill.png` — original image with the detected region
  outlined in red (other candidate dark regions, e.g. look-alikes, shown
  faintly in yellow) and a confidence label.
- `output/result.json` — the machine-readable result, matching the
  contract other modules (drift, AIS) will consume:

  ```json
  {
    "detected": true,
    "latitude": 13.10,
    "longitude": 80.30,
    "confidence": 0.91
  }
  ```

  (extra diagnostic fields like `contrast_vs_background` and
  `num_candidate_regions` are included too, but the four core fields
  above are the stable contract.)

**Note on lat/lon:** `13.10, 80.30` is fixed demo metadata, not
something extracted from the image. In a real system this comes from
the satellite scene's own geolocation metadata.

## 5. How it works (pipeline)

1. **Load** image as grayscale.
2. **Preprocess** — median blur to suppress SAR speckle noise.
3. **Threshold** — Otsu's method finds dark ("candidate") regions.
4. **Clean up** — morphological open/close removes tiny noise specks
   and fills small holes.
5. **Score each candidate region** on:
   - size (relative to frame)
   - elongation (oil slicks streak with wind/current; noise/sensor
     artifacts tend to be more compact)
   - irregularity (rough boundary vs. a smooth circle)
   - **contrast vs. background** (a real dark feature is meaningfully
     darker than the surrounding sea — this is what prevents pure
     speckle noise from being mistaken for a spill)
   - a sanity cap: a "region" covering most of the frame is treated as
     a bad threshold split, not a real localized spill
6. **Pick the best-scoring candidate** (not simply the largest dark
   region) as the primary detection, so an obvious look-alike doesn't
   win just by being big.
7. **Decide "detected"** only if both the oil-likelihood score and the
   contrast are above minimum thresholds.
8. **Annotate + save** the output image and JSON result.

## 6. Robustness

The script handles, without crashing:
- missing image file
- unreadable / invalid image file
- no significant dark region found (returns `"detected": false`)
